# parallel-linear-solver

Решение систем линейных уравнений методом вращений с блочным хранением матрицы, многопоточная реализация на C++. Плюс поиск собственных значений симметричной матрицы.

Учебный проект в рамках спецкурса «Основы параллельных вычислений» (механико-математический факультет МГУ, преп. Богачёв К. Ю.).

---

## Что внутри и структура проекта

Проект разбит на три директории, каждая из которых содержит свою независимую программу:

**1. `1_sequential` - Задача 1. Решение СЛУ методом вращений.**
Матрица хранится блоками - так обращения к памяти попадают в кэш, а не бьют по произвольным адресам. Приведение к верхнетреугольному виду вращениями Гивенса, затем обратный ход. Реализована оценка невязки и проверка на матрицах с известным решением.

**2. `2_parallel` - Задача 2. Распараллеливание.**
Та же задача, разделённая между потоками: блочные операции распределяются по потокам (используется `pthreads`), синхронизация на границах шагов через барьеры. Замеряется ускорение относительно однопоточной версии и его зависимость от числа потоков (измеряется процессорное и реальное время).

**3. `3_eigenvalues` - Задача 3. Собственные значения.**
Поиск собственных значений симметричной матрицы. Сначала матрица приводится к трехдиагональному виду, затем применяется итерационный алгоритм. Проверка по следу и сумме квадратов элементов - инварианты, которые должны сохраняться.

---

## Почему метод вращений, а не исключение Гаусса

Вращения Гивенса численно устойчивее: ортогональные преобразования не увеличивают число обусловленности, тогда как исключение Гаусса без выбора главного элемента может катастрофически терять точность. Цена - больше арифметических операций.

---

## Блочное хранение

Матрица разбивается на блоки, помещающиеся в кэш процессора. Операции идут над блоками целиком, поэтому одна загрузка из памяти обслуживает много арифметических действий. На больших размерностях это даёт разницу в разы при том же числе операций - узкое место в таких задачах не процессор, а память.

## Сборка и запуск

Каждая программа собирается внутри своей папки командой `make`. 
Матрица либо читается из файла, либо генерируется по формуле - для генерируемых вариантов известно точное решение, что позволяет измерять фактическую погрешность, а не только невязку.

### 1. Последовательный решатель СЛУ (`1_sequential`)
```bash
cd 1_sequential
make
./solver <n> <m> <r> <s> [filename]
```
* `n` - размерность матрицы.
* `m` - размер блока.
* `r` - количество выводимых значений (для печати матриц).
* `s` - режим работы (номер формулы для генерации). Если `s = 0`, требуется указать имя файла.
* `filename` - путь к файлу с матрицей (указывается только если `s = 0`).

### 2. Параллельный решатель СЛУ (`2_parallel`)
```bash
cd 2_parallel
make
./solver <n> <m> <p> <r> <s> [filename]
```
* `n` - размерность матрицы.
* `m` - размер блока.
* `p` - количество потоков.
* `r` - количество выводимых значений.
* `s` - режим работы (0 - чтение из файла, >0 - генерация по формуле).
* `filename` - путь к файлу (если `s = 0`).

### 3. Поиск собственных значений (`3_eigenvalues`)
```bash
cd 3_eigenvalues
make
./solver <n> <m> <eps> <k> [filename]
```
* `n` - размерность матрицы.
* `m` - количество выводимых значений.
* `eps` - требуемая точность вычислений (например, `1e-6`).
* `k` - режим работы (0 - чтение из файла, >0 - генерация по формуле).
* `filename` - путь к файлу (если `k = 0`).

## Формат вывода результатов

Программы завершают свою работу стандартизированным выводом вида:
```text
./solver : Task = 21 Res1 = ... Res2 = ... T1 = ... T2 = ... S = ... N = ... M = ... P = ...
```
Где:
* `Res1` - норма невязки (или первая погрешность).
* `Res2` - норма погрешности решения.
* `T1` - время выполнения основной вычислительной части.
* `T2` - время дополнительных вычислений (например, подсчет невязки).
