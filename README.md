# parallel-linear-solver

Решение систем линейных уравнений методом вращений с блочным хранением матрицы,
многопоточная реализация на C++. Плюс поиск собственных значений симметричной матрицы.

Учебный проект в рамках спецкурса «Основы параллельных вычислений»
(механико-математический факультет МГУ, преп. К.Ю. Богачёв).

---

## Что внутри

**Задача 1. Решение СЛУ методом вращений.**
Матрица хранится блоками — так обращения к памяти попадают в кэш, а не бьют
по произвольным адресам. Приведение к верхнетреугольному виду вращениями Гивенса,
затем обратный ход. Реализована оценка невязки и проверка на матрицах
с известным решением.

**Задача 2. Распараллеливание.**
Та же задача, разделённая между потоками: блочные операции распределяются
по потокам, синхронизация на границах шагов. Замеряется ускорение
относительно однопоточной версии и его зависимость от числа потоков.

**Задача 3. Собственные значения.**
Поиск собственных значений симметричной матрицы; проверка по следу
и сумме квадратов элементов — инварианты, которые должны сохраняться.

---

## Почему метод вращений, а не исключение Гаусса

Вращения Гивенса численно устойчивее: ортогональные преобразования не увеличивают
число обусловленности, тогда как исключение Гаусса без выбора главного элемента
может катастрофически терять точность. Цена — больше арифметических операций.

---

## Блочное хранение

Матрица разбивается на блоки, помещающиеся в кэш процессора. Операции идут
над блоками целиком, поэтому одна загрузка из памяти обслуживает много
арифметических действий. На больших размерностях это даёт разницу в разы
при том же числе операций — узкое место в таких задачах не процессор, а память.

---

## Сборка и запуск

```
make
./solver <размер> <размер_блока> <число_потоков> <режим> [файл_матрицы]
```

Матрица либо читается из файла, либо генерируется по формуле —
для генерируемых вариантов известно точное решение, что позволяет
измерять фактическую погрешность, а не только невязку.
